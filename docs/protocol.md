# Форматы и метод сравнения

## NTP

Клиент отправляет NTPv4 mode 3 и принимает ответы mode 4 версий 3/4. Проверяются длина, originate timestamp, stratum, LI, ненулевые и упорядоченные серверные метки. Ответ Kiss-o'-Death останавливает тест.

```text
offset = ((t2 - t1) + (t3 - t4)) / 2
delay  = (t4 - t1) - (t3 - t2)
delta  = offset_MNAV - offset_UKUS
```

Положительный offset означает опережение часов ПК, положительная delta — опережение УКУС. Длительность запроса измеряется монотонными часами. При обнаруженном скачке часов ПК цикл исключается. Статистика по 20% пар с наименьшей суммой delay показывает отдельный срез, а не исправленную абсолютную точность.

Кандидаты времени в блоках ТО и время NMEA не используются для оценки точности PPS.

Спецификация: [RFC 5905](https://datatracker.ietf.org/doc/html/rfc5905).

## Экспериментальный протокол ТО УКУС

UDP/10554. Это собственный бинарный формат, не исходный NMEA. Реализована только наблюдаемая команда чтения состояния `0x0005`. Команд записи нет.

Профиль: CSM24 04.08 / NV08C 07.03. Для других прошивок декодирование координат не выполняется. Интерпретация получена экспериментально и не является документацией производителя.

Все целые поля little-endian:

| Смещение | Байты | Поле |
|---|---:|---|
| 0 | 2 | Маркер `0x5BAD` |
| 2 | 2 | Номер транзакции |
| 4 | 2 | Длина после первых 10 байт |
| 6 | 2 | Сумма байт с позиции 2, кроме 6 и 7, modulo 65536 |
| 8 | 2 | Чтение `5`, ответ `0x85` |
| 10 | 2 | Смещение блока |
| 12 | 2 | Длина данных |
| 14 | N | Данные ответа |

Читаются блоки `(offset=0, length=252)` и `(offset=252, length=170)`.

Блок 0:

- +40: строка версии CSM24, 32 байта;
- +72: строка версии NV08C, 32 байта;
- +128…251: 31 запись канала по 4 байта — тип, ID, дополнительное поле, уровень сигнала.

Типы каналов: 0 — пусто, 1 — GPS, 2 — ГЛОНАСС, 4 — SBAS. Поле уровня интерпретируется как дБ·Гц. Использование спутника в решении и канал 32 неизвестны. Первые байты следующего блока не считаются автоматически продолжением массива.

Блок 252, смещения от начала данных:

- +4: широта float64 LE, радианы;
- +12: долгота float64 LE, радианы;
- +20: высота float64 LE; тип высоты требует подтверждения;
- +44/+48: целые поля, назначение не подтверждено; не используются как достоверные метки эпохи.

Флаги достоверности и система координат требуют независимой проверки. Высота сравнивается только после выбора оператором подтверждённого типа MSL/эллипсоид.

## NMEA МНАВ

Пассивное чтение TCP-потока, по умолчанию порт 6006. Команды в приёмник не отправляются. Строки собираются независимо от границ TCP-пакетов, checksum обязателен.

- GGA: координаты, качество, высота MSL, разделение геоида, число спутников, HDOP.
- RMC: координаты, дата/время, статус, скорость в узлах.
- VTG: скорость в км/ч или узлах.
- GSA: DOP и спутники в решении.
- GSV: спутники в поле зрения, сигнал, C/N₀, возвышение, азимут.

GGA/RMC объединяются только при совпадении времени предложения. Отсутствующие поля не заменяются нулями. Повтор одной эпохи стареет, даже если строки продолжают поступать. GSV публикуется после полного набора частей, отдельно для talker/signal ID; старые наборы исключаются. Скорость в км/ч выводится только из явно переданного допустимого поля при достоверном решении.

## Тестовые данные

`test/fixtures/ukus.json` и `ukus-2.json` полностью синтетические: созданы по структуре протокола, с условными координатами около 50°/30°, документальными IP 198.51.100.0/24 и искусственными временными метками. Неизвестные поля заполнены нулями. Fixtures не содержат исходных пользовательских пакетов.
